# 候选联合复核与正式合片

3.0新增 `quality_review.py`。它校验实际复核记录的完整性及其对应的文件，不做自动人数、脸或雨伞识别。视觉判断仍由制作agent根据原片与候选完成。用户只需审阅视频，运行命令和填写记录由agent处理。

## 使用

在独立工作副本离线安装升级后的运行文件，安装器保留旧脚本、任务状态、凭据和已配置的音乐：

```text
python <技能目录>/scripts/bootstrap_runtime.py --project <工作副本> --apply
python <工作副本>/quality_review.py prepare --project <工作副本>
```

准备命令读取正式选片和原始帧数表，生成 `制作分析/candidate_reviews.json`。只为已选片生成待查记录；不提交任务，不修改正式选片，也不把任何视觉项自动写成通过。再次运行会保留输入哈希不变的记录，换过候选、运动源或身份图的条目恢复为待查。

每条记录需要：

- `binding`：脚本计算的候选、原运动源、两张身份图SHA256与保留帧数。候选是已选的输出文件；运动源是工作副本根目录 `补齐生成用` 的原动作视频。不要手改哈希来继承旧复核。
- `reviewed_frame_ranges`：实际检查过的本地帧区间，闭区间、从0开始，例如013全部84帧是 `[[0,83]]`。少量截图不代表全部帧已查。
- `source_frames_checked`：实际对照过的原片帧。一般至少首末保留帧；013还要对照18、32、50、75帧，防止只看披衣而漏掉撑伞动作。
- `checks`：身份、人数、道具归属、动作节奏、衣物交接、肢体遮挡、画面瑕疵、相邻衔接各项。实际通过后才填 `pass`，有问题填 `fail`，未查保持 `pending`。
- `observations.source_roles_present`：整段实际存在的源动作角色ID；按源片人数映射本次人物。临时被遮住不等于消失，017仅有一号手臂是正常局部镜头，不要求出现完整身体。
- `observations.umbrella_operator`、`outer_garment_owner`：013分别应是 `source_1`、`source_2`。这些ID指动作角色，与本次参考图性别、颜色及Picture槽位编号分开。
- `reviewer`、`notes`：实际复核者与具体观察，包含走位、道具及衔接判断。`dynamic_review`记录真实原速复核的状态、复核者和观察。文件成功解码或接触表不能代替原速观看。

准备文件中的 `review_guidance` 仅作提示；校验脚本内有013动作归属约束，修改提示内容不能改变该约束。人数预期读取本模板的帧数角色表，包内文字方向与画面冲突时另以原片纠正站位。未经用户要求改变源剧情时，不把二号改为撑伞者。

复核后先离线检查，再正式合片：

```text
python <工作副本>/quality_review.py check --project <工作副本>
python <工作副本>/assemble.py --check-only
python <工作副本>/assemble.py
```

`quality_review.py check`验证记录；`assemble.py --check-only`还核对正式选片和未决问题。正式合片保留原有的1417帧、24fps、音乐、画幅与许可metadata检查。记录缺失、仅衣服通过、原速未查、旧候选记录失效、013只有二号或由二号撑伞时停止，不启动编码或重生成。

已有旧版项目的 `static_passed` 不会自动转换成联合复核通过；升级后由agent补充真实检查记录。验证失败时修复对应问题或补齐未做的检查，不改状态绕过。通过记录本身也不能取代画面质量判断。

## 本次013回归案例

约39.71～43.21秒是013，截图41秒对应局部约1.29秒。`wrap_owner`保住粉色披衣，却漏掉一号并让二号撑伞，应拒绝；原始主候选保住双人和一号撑伞，但披衣不连续，仍不能宣称全部通过。分别记录人数、撑伞者和披衣衔接，避免在两种缺陷之间换版后就声称修好。

需提前给用户看时，可用单独的完整复核版和选片清单列明未决问题，不能修改正式清单或将未查记录批量通过。展示时在最终回复中嵌入本地视频并附绝对路径；用户看不到播放器时给出已存在文件的可点击路径，不反复要求审阅不可见视频、不接管其桌面。
